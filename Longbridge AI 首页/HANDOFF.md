# Longbridge Web 登录态首页 · Claude Code 交接文档

## 项目概述

Longbridge（长桥）是服务 HK/SG 市场的金融交易平台。本项目是 Web 端登录态首页的全新设计——一个「生产平台 + 感知层」的 AI 原生应用。

当前阶段：**单文件 HTML 原型（v17，1261 行）**，需要演进为可交互的多文件 demo，增加交互深度和布局精细度。

## 产品架构

### 五列布局节奏

从左到右：**导航 → 浏览 → 详情 → AI 工作台 → chat**

```
┌─ 顶部导航（60px · #0a0a0d）────────────────────────────────────────┐
│ Logo + 指数条 (恒生/国企)    营销菜单    🔍🎧🌐 头像              │
├─────┬────────────────────┬─────────────┬──────┬────────────────────┤
│icon │ 主浏览区            │ 详情(可选)  │ AI   │ Chat               │
│导航  │ flex-1             │ 0→320px     │工作台 │ 280px              │
│52px │ 动态切换            │ 右侧滑入    │240→  │                    │
│     │                    │             │208   │                    │
├─────┴────────────────────┴─────────────┴──────┴────────────────────┤
│ 全局 AI 输入框（54px · 横跨底部 · max-width 720px）                 │
└──────────────────────────────────────────────────────────────────────┘
```

- **默认态（4列）**：icon导航 + 主浏览区 + AI工作台(240px) + Chat(280px)
- **展开态（5列）**：详情列(320px)从浏览区右侧滑入，AI工作台自动收窄至208px
- **跨视图持久**：切换主内容区视图时，详情列保持不变

### 设计原则

1. **GUI + Chatbot 混合交互**：左侧 GUI 保效率，右侧 Chat 增灵活，两者融合不分离
2. **固定框架 + 动态内容**：AI工作台/chat/输入框始终在，主内容区动态切换
3. **信息类 + 功能类拆解**：Push类→时间线事件，Pull类→Widget卡片+icon导航

## 当前已实现功能（v17）

### 1. 顶部导航
- 深色背景 #0a0a0d，沿用 longbridge.com 营销菜单
- Logo（四色条纹 + Hong Kong + LONGBRIDGE）
- 指数条（恒生/国企，带 sparkline 和涨跌色）
- 右侧：菜单项 + 搜索/客服/语言图标 + 头像

### 2. 左侧 icon 导航（52px）
- 三组：首页(带badge) | 自选/资产/资讯 | 市场/社区/交易
- 选中态：#00d4a1 前景 + rgba(0,212,161,.08) 背景

### 3. 主浏览区（首页）
- **持仓总览条**：总资产 + 今日变化 + Top 3 持仓
- **变化事件时间线**：未读→分割线→已读，支持事件点击行为分离
- **Signal 富卡片**（v17 新增）：公司logo + ticker + 迷你走势图 + Verdict标签 + 标题 + 描述 + 策略名
- **Widget 列表卡片**：4张大卡（Watchlist/Portfolio/Market/P&L），可直接阅读级信息密度

### 4. 详情列（320px）
- **普通标的详情**：代码+名称 → 价格 → 走势图(canvas) → 6格关键数据 → 操作按钮
- **Signal 详情**（v17 新增）：Final verdict(4格) → Related catalysts → Strategy fit score(圆环仪表盘+因子列表) → Analysis process → Valuation range(色条) → Risk warning → Execution rules → Build trade plan CTA

### 5. AI 工作台（240px/208px）
- 三类内容：AI长期任务 + 活跃策略 + 长期订单
- 四种状态：运行中(橙) / 正常(绿) / 预警(红闪烁) / 已暂停(灰)
- 原地操作按钮

### 6. Chat 列（280px）
- 上下文标签 + 消息流 + 快捷问题

### 7. 全局 AI 输入框
- 三态：静默 → 聚焦(AI绿边框) → live-morph(渐变+脉冲点)
- 上下文提示 + 快速意图 chips

### 8. 五类动态视图（实时布局重组）

用户打字时主浏览区实时重组，不需要回车：

| 类型 | 触发关键词 | 优先级 | 已实现 |
|------|-----------|--------|--------|
| 对比决策 | 对比/比较/vs/哪个好 | 1（最高）| ✅ NVDA vs AMD |
| 策略构建 | trade plan/建单/止损/期权 | 2 | ✅ NVDA Long Call |
| 归因诊断 | 为什么跌/为什么亏/归因 | 3 | ✅ 瀑布图+宏观因素 |
| 标的研究 | [标的]+能追吗/基本面 | 4 | ✅ NVDA 深度研究 |
| 风险审视 | 风险/持仓/组合 | 5（兜底）| ✅ 组合风险页 |

### 9. 场景切换
- 活跃日 / 平静日 / 下跌日 三个 demo 场景
- 联动指数条、持仓总览、时间线、AI工作台状态

## 关键设计决策（已确定）

| 决策 | 说明 |
|------|------|
| 事件点击行为分离 | 点击主体=已读，点击蓝色 ticker pill=详情 |
| 实时动态布局 | input事件触发，不需要回车；Enter只发送给AI |
| AI工作台命名 | 替代了「感知敞口」，用户可理解 |
| 输入框位置 | 全局底部（AI是核心），不在chat列内（那样AI是补充） |
| 详情列位置 | 浏览区和AI工作台之间——是浏览延伸，不是AI输出 |
| 意图分类器优先级 | 对比>策略>归因>标的>风险（处理多关键词冲突）|
| P0用正则 | 后续接入AI模型做fallback |

## 技术建议

如果要在 Claude Code 中继续，建议：

1. **保持单页应用**：不需要框架，vanilla JS + CSS 变量就够。原型阶段不引入 React/Vue
2. **文件拆分但不过度**：拆到 5-8 个文件即可，不需要完整的工程化
3. **状态管理简化**：用一个全局对象 + 事件派发，不需要 Zustand
4. **图表用 Canvas**：走势图和迷你图继续用 Canvas 手绘，不引入 Chart.js
5. **本地开发**：`python -m http.server 8080` 或 `npx serve` 即可
